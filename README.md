# 美团 App「更换手机号」流程自动化

纯 Python 自动化脚本：连接安卓手机后，自动完成
**美团登录页 → 右上角「帮助」→「遇到问题」→「更换手机号」→ 填号 → 一直「下一步」**，
直到页面出现模糊（打星）的姓名与身份证号，自动截图取证。

- **交付物就是本脚本这一个 .py 文件**：所有运行参数已内置为默认值，拿到即可运行
- 仅依赖 Python 3.8+ 标准库 + adb，不装任何第三方包、不在手机上装任何东西
- 全流程无人工干预：退出登录、页面导航、填号、读短信验证码、滑块验证、提交全部自动
- 起点自适应：没装美团会自动下载安装，没打开会自动拉起，停在任意页面会自动归位到流程起点

## 环境要求

1. Python 3.8+（无 pip 依赖）
2. adb（Android platform-tools），或用 `--adb` 指定路径
3. 安卓机开启 USB 调试并连接电脑（vivo 机型还需开「USB 调试（安全设置）」才能模拟点击）
4. 换绑目标手机号可接收短信

## 快速开始

```bash
# 全自动（唯一必填项：--phone 换绑目标号）
python auto_change_phone.py --phone 13800001234 --valid-hours 48 \
    --adb C:/platform-tools/adb.exe

# 不带 --phone 直接运行：脚本会在控制台提示，键盘输入 11 位手机号即可
python auto_change_phone.py

# 人工已操作到某一步，从当前手机状态直接接管
python auto_change_phone.py --manual-login
```

成功时控制台输出 `[DELIVERABLE] <取证截图绝对路径>`，退出码 0。

## 命令行参数

| 参数 | 说明 |
|------|------|
| `--phone` | 换绑目标手机号（11 位大陆手机号），唯一必填参数；不填时脚本运行中会提示键盘输入 |
| `--serial` | adb 设备序列号；多台设备时必填，单台自动识别 |
| `--adb` | adb 可执行文件路径（默认取 PATH 里的 adb，或环境变量 ADB_PATH） |
| `--config` | JSON 配置文件路径，**可选**：与内置默认配置逐字段合并，只写要覆盖的字段 |
| `--manual-login` | 跳过自动退出登录，从当前手机状态接管 |
| `--fresh-identity` | 运行前执行**身份重置**：pm clear 清美团数据 + adb 免 root 换新 Android ID + 首启注册全新 dfpId。用于设备被风控关联（滑块反复判负）后以全新设备身份重试；实测换新身份后服务端会改发可解的连线验证而非死拒滑块 |
| `--valid-hours` | 有效期小时数（如 48；0=不限期；不填用内置默认 48） |
| `--log-level` | DEBUG / INFO / WARN / ERROR |
| `--observe-net` | 被动采样运行期间设备的 TCP 远端端点（netstat 轮询，纯本地观测、对 App 与服务端零影响），去重写入 `logs/net_endpoints.log`，并计入 `[SUMMARY]` 的 `net_endpoints` 字段；用于协议分析取证（验证流程打哪些网关） |

## 配置说明（已内置，可选覆盖）

所有运行参数已内置在脚本 `DEFAULT_CONFIG` 中，**直接运行无需任何配置文件**。
需要微调时两种方式（优先级：命令行参数 > `--config` JSON > 内置默认值）：

```json
{ "max_next_submit": 3, "flow_timeout_sec": 600 }
```

```bash
python auto_change_phone.py --phone 13800001234 --config my_overrides.json
```

常用字段：

| 字段 | 内置默认 | 说明 |
|------|------|------|
| `phone` | 空 | 换绑目标手机号；三种给法任选：`--phone` 参数 / 运行时按提示输入 / `--config` JSON 里写 `"phone"` |
| `valid_hours` | 48 | 有效期，首次运行起算；0=不限期；删除 `.mt_auto_expire` 文件重置计时 |
| `max_next_submit` | 2 | 「下一步」提交次数上限（防风控加重的保护，可按需调大） |
| `max_slider_attempts` | 3 | 滑块被服务端反复拒绝的停机阈值 |
| `max_connect_attempts` | 6 | 连线验证按色尝试轮数上限（黄→蓝→红→绿，弹窗消失即通过） |
| `connect_pixel_probe` | true | 文本未命中时的像素级连线题兜底探测（弹窗为 WebView 时标题可能不在 UI dump 里） |
| `fresh_identity` | false | 同 `--fresh-identity`；命令行参数优先 |
| `captcha_solver_url` | 空 | 可选打码服务地址：遇到点选类验证（图标点选/文字点选/空间推理）或字符验证码时 POST base64 截图（请求体含 `image`/`img1`/`img2` 三个同源键，兼容点选类服务的大图+提示小图双图协议）。响应兼容四种形态：`{"points":[[x,y],...]}`、`{"data":{"points":...}}`、`{"res_str":"[[x,y],...]"}`（得塔云等）、`{"text":"8347"}`（字符验证码，自动填入输入框）。坐标按序拟人点选（±3px 抖动 + 0.35-0.9s 随机间隔），每轮后复查弹窗，最多 `max_tap_attempts` 轮；不配置或全部失败则留证停机，不盲点 |
| `max_tap_attempts` | 3 | 点选类验证打码解题轮数上限 |
| `tap_settle_sec` | 2 | 点选动作完成后复查弹窗前的等待秒数 |
| `flow_timeout_sec` | 300 | 单轮流程超时 |
| `ref_resolution` | [1080,2400] | 坐标校准基准分辨率；换机时改 coord_steps 或声明新的基准 |

内置的 `coord_steps` 是流程页点击步骤表（H5 页面无控件文本，按校准坐标走）：
每步优先按 `locate` 语义定位（文本/描述/控件类型），未命中时坐标按
实际分辨率与基准分辨率的比例自动缩放。**更换机型请通过 `--config` 覆盖
`coord_steps` 重新校准各步坐标**（在目标机上手动走到对应页面，用
`adb shell uiautomator dump` 查看控件位置）。

## 脚本自动做什么

1. 检查美团：未安装则自动下载官方 APK 并安装（预授运行时权限）
2. **熄屏唤醒**：自动唤醒屏幕、尝试解锁（无密码滑动锁），USB 供电期间保持常亮（`svc power stayon usb`，拔线自动恢复）；有安全锁时告警提示人工解锁
3. 已登录则自动 我的 → 设置 → 退出登录（「帮助」入口只在登录页可见）
4. 到登录页 → 右上角「帮助」→「遇到问题」→「更换手机号」
5. 填入手机号（逐字注入防吞字）→ 短信验证码自动从通知栏读取并填入
6. 滑块验证按拟人轨迹自动拖动（uinput 真触摸流优先，失败降级拟人运动流）
7. **连线验证**（「用最短线连接X色验证」）自动识别同色圆点并连线，
   失败自动换色重试（黄→蓝→红→绿），弹窗消失即通过
8. 循环点「下一步」，直到页面出现模糊姓名/身份证号 → 截图取证收工
9. 中途遇到风控提示（行为异常/请求次数过多等）自动停机保护，避免加重风控；
   遇点选类验证（图标/文字/空间推理）走 `captcha_solver_url` 打码服务自动解题
   （坐标按序拟人点选 / 文本自动填入），未配置打码服务才留证停机
10. 验证检测三通道互备：UI 文本 → 窗口焦点组件标记（captcha/verify/yoda，
    WebView 弹窗标题不在 UI dump 时兜底）→ 连线像素探测；组件通道连续
    2 轮命中且排除连线题后才按点选验证处置，零误报优先
11. **R31/R32 行为去指纹**：所有等待统一乘随机抖动因子（跨次运行时间线
    不再逐毫秒相同）；逐字输入变间隔+偶发停顿（防 keystroke 节奏指纹）；
    验证失败重试按轮次递增退避（连线/点选/滑块），不立即重试；
    组件点击 ±2px 微抖 + 拟人按压时长（`tap_human`：DOWN→50-150ms→UP，
    替代 0ms 按压的 `input tap`）；连线滑动走变速近直线事件流
    （`motion_line`，替代 `input swipe` 的等间隔匀速采样，端点钳制在
    圆点内保证「最短线」语义）；空闲轮次越多轮询越稀（降低 dump 频率）；
    Android ID 换新用小写 hex（真实 SSAID 格式）；退出时还原
    `stay_on_while_plugged_in` 系统设置（抹掉调试指纹）
12. **R33 拼图滑块解算**（2026-11-14 真机实战验证）：冷启动「请拖动下方
    滑块完成拼图」纯像素解算——黄色把手（最长连续段判定抗版式干扰）→
    照片带（行内容占比，校验「照片带在把手上方」排除普通滑块误检）→
    缺口双路（实心深灰块连通域＝亮色照片；多带水平梯度峰对投票＝暗色
    照片兜底）→ 拖动距离按轨道-图像比例换算。拖动用快速水平直线
    （`motion_line` 420ms——vivo 实测 1100ms 曲率轨迹 6 连拒、330ms
    直线一次过）。华为真机一发命中，vivo 真机检测全中
13. **R33 普通滑块解算**（vivo 真机实战验证）：「请向右滑动滑块验证」
    （拖到最右型）——黄把手 + 把手行浅灰长滑轨（≥500px）+ 把手上方
    无照片带（与拼图弹窗区分），快速直线拖到轨道右端，第 2 次尝试通过
14. **R33 图像理解类验证降级处置**：点选/字符码等需 OCR/打码钩子的题型
    （vivo 高风险会话实测只发此类题，刷新 43 次不变），迷路钩子检测
    「请依次点击/请输入图片」文本后自动点刷新按钮换题；换不出可解题时
    由退出登录/流程超时兜底（`logout_timeout_sec` 420s，为连环验证
    留处置预算）
15. **R34 图标点选题本地秒级求解**（2026-11-14 vivo 真机实战验证）：
    「请依次点击下图图标」零依赖离线求解——提示条识别（白底外圈黑
    剪影图标同行近等距聚类，白条分割碎片自动合并）→ 照片区候选（含
    干扰项过滤）→ 16x16 二值 XOR 形状匹配按序配对（实测匹配对角
    距离 ≤0.14、错配 ≥0.21，判异阈值 0.18）→ 拟人连点（±3px 抖动
    + 0.35-0.9s 随机间隔）→ 复查弹窗；判错自动续解新题、匹配不过
    自动刷新换题。全程约 4 秒，远快于验证码会话时效（vivo 实测
    「授权码已过期」败因＝人工分析超 3 分钟）。外网无现成题库
    （Yoda 点选为服务端动态生成），此路线为最优解
16. **R36 字符码免费离线兜底（内嵌 ddddocr，单文件零配置）**：OCR
    能力直接缝在主脚本进程内——不再有独立桥进程/HTTP 端口/第二个
    py 文件。几何定位跑在主脚本自己的纯 stdlib PNG 解码上（彩色
    字符带 → 暗墨字符带 → ddddocr 目标检测三路），裁剪由内置
    PNG 编码器（zlib+struct 手写 chunk）输出，小图自动 2 倍放大。
    ddddocr（MIT、免费、离线推理）**不在交付依赖里**：只在真遇到
    「请输入图片字符」题型时懒加载 import，缺包自动 pip 安装
    （腾讯云/阿里云/官方镜像依次兜底），且页面文本闸门保证只对
    字符码题型出手（图标点选页不会被 OCR 读出乱码去乱填）。
    客户端只跑一条命令，什么都不用配：
    ```
    python auto_change_phone.py --phone 13800001234
    ```
    仍可配置 `captcha_solver_url` 接超级鹰等付费打码平台（配置后
    走外部服务，不用内嵌 OCR）。端到端实测：整屏截图 → 几何定位
    → 识别 '8347' 精确命中 3.4s（首次含模型加载约 10s 内）

## 输出说明

| 文件 | 说明 |
|------|------|
| `output/mt_masked_*.png` + `.txt` | **验收产物**：模糊身份信息截图 + 命中文本与页面全文 |
| `output/coord_*.png` | 流程每步截图（过程留痕） |
| `output/mt_stuck_debug.png` 等 | 停机/卡住时的现场截图 |
| `logs/run_*.log` | 分级运行日志（手机号已脱敏） |
| `.mt_auto_expire` | 有效期计时锚点（首次运行自动生成，删除即重置计时） |

失败时 stderr 输出机器可读摘要行：
`[FAILURE] category=<adb|risk|ratelimit|timeout|stuck|config> log=<日志路径>`。
无论成败，结束前 stderr 会输出一行 `[SUMMARY] {...}` 结构化 JSON（含 exit/category/serial/phone 掩码/滑块次数/连线轮次/端点采样数），供上层调用方程序化解析。

## 退出码

| 码 | 含义 |
|----|------|
| 0 | 完成（拿到取证截图） |
| 2 | 无设备 / adb 错误 |
| 3 | 超时 |
| 4 | 页面卡死 / 「下一步」限次用尽 |
| 5 | 配置错误（含参数错误、--phone 非法、有效期已过） |
| 6 | 服务端风控终审拒绝（行为异常/滑块判负）——**应换号或走申诉，不要重试** |
| 7 | 频控/配额限流（请求次数过多类提示）——**计数器性质，冷却后可恢复**，与 6 的死拒不同 |

## 注意事项

- **换号冷却**：更换手机号有频控，被限流（退出码 7）时换号或等次日配额重置，不要高频重跑
- **验证码**：验证码短信到达后脚本自动读取（读通知栏）；读取失败会自动等待重试
- **双机并发**：多台手机可同时跑（输出文件自动带设备序列号前缀，互不覆盖）
- **设备风控关联**：滑块反复判负时服务端已把设备身份拉黑，此时用
  `--fresh-identity` 以全新设备身份重试（pm clear + Android ID 换新 +
  重新注册 dfpId）；若仍被关联，可在手机上开启华为「隐私空间」等第二用户
  （Android 8+ 的 Android ID 按用户隔离），在第二用户里安装美团后重跑
- **版本变更**：美团改版导致文案/布局变化时，用 `--config` 提供一份 JSON
  （可只写要覆盖的字段）调整 `coord_steps` 坐标表与关键字即可
